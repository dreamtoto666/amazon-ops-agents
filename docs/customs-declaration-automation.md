# 报关单填写自动化

## 范围

“报关单填写”是独立的确定性处理功能，不调用 LLM、LangGraph、MCP 或数据库。每次请求只接收：

- 一八发货模板 `.xlsx`，读取“美国专线箱单”；
- FBA 货件表 `.xlsx`，读取“装箱明细”和“货件详情”（兼容“货件详细”）。

系统按“普船统配/快船/美森极致达/普船特惠 × 0110/9810”预览八类数据，只为有货分类生成报关单，最后返回一个 ZIP。原始文件、预览结果和生成文件都不持久化。

## 数据规则

- 客户原单号固定以“美国专线箱单”D 列为准；分类内去重，同一单号跨分类是阻断错误。
- “装箱明细”中的货件单号、总箱数和总重量按货件分组向下继承；其品名、SKU、申报量不参与统计。
- “货件详情”中的货件单号按行向下继承，R 列品名、S 列 SKU、T 列申报量为商品明细来源；商品行全部累加，不去重。
- 品名匹配优先于 SKU。程序忽略颜色词，规范大小写、米制单位和乘号，再按产品类型和尺寸匹配内置目录。
- SKU 仅用于冲突提示；冲突时仍按品名结果统计。
- 全部商品使用目录中的 35% 报关单价。
- EPDM 使用 HS `4016939000`；其他材质使用 `3926909090`。
- 箱数和毛重每个货件只累计一次；总净重固定为总毛重的 92%。
- 商品目录单件重量仅用于分配比例，商品毛重和净重按该比例分摊到两位小数，最后一项吸收尾差。
- 商品金额使用 `Decimal` 计算并保留两位小数。

商品目录位于 `src/amazon_ops/customs_declaration/resources/product_catalog.v1.json`。新增或修订商品时发布新版本资源，不在处理代码中增加特例。

## 模板与输出

内置模板按贸易方式分别位于 `src/amazon_ops/customs_declaration/resources/customs_declaration_0110.v1.xlsx` 和 `customs_declaration_9810.v1.xlsx`。生成器按贸易方式选择模板，并直接修改 OOXML 中的指定单元格，不通过工作簿重存，因此会保留六个工作表、图片、线条、打印区域、固定内容和联动公式。

每个商品占“报关单”三行。0110 模板最多 23 个标准商品，9810 模板最多 16 个；超过容量会阻止本次全部生成。程序只填写日期、商品信息、数量、价格、金额、净重、毛重和首项箱数；每个商品首行固定写入中国、美国、河北邢台、照章征税，运费保留模板原值。工作簿设置为打开时自动完整重算。

输出文件名：

```text
{合同号}-美国海运-{普船统配、快船、美森极致达或普船特惠}-{0110或9810}-{箱数}箱-报关单-{金额取整}美元.xlsx
```

ZIP 文件名：`{YYYYMMDD}-报关单.zip`，日期使用 `Asia/Shanghai` 当天。

## API

- `POST /api/customs-declarations/preview`：认证 multipart 请求，字段为 `shipment_file` 和 `fba_file`。返回八类汇总、商品、警告和阻断错误。
- `POST /api/customs-declarations/generate`：重新校验同一组文件。成功返回 `application/zip`；失败返回结构化 `422` 预览结果。

前端只能通过 `frontend/src/app/api/customs-declarations/` 下的同源代理访问这两个接口。

## 安全和失败行为

- 只接受 `.xlsx`，单文件上限 20MB；限制 ZIP 文件项、展开大小和工作表行数。
- 使用只读、`data_only` 模式解析输入，不执行公式，也不把输入单元格内容当作公式或指令。
- 未知品名、缺失货件、非法数量或重量、分类冲突、损坏文件和模板容量不足均为阻断错误。
- 任一阻断错误都会停止全部生成，不返回部分文件。
